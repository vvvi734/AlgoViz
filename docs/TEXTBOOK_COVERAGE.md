# 教材课程覆盖表

知识体系与章节顺序以严蔚敏、吴伟民《数据结构（C语言版）》（清华大学出版社，1997 年 4 月第 1 版）为主要参考；通俗讲解与典型应用选材参考程杰《大话数据结构（溢彩加强版）》（清华大学出版社，2020 年修订版）。两本书的章节、印刷页与 PDF 页索引见 [`REFERENCE_BOOKS.md`](REFERENCE_BOOKS.md)。

## 教材使用原则

- 12 章作为一级大纲，保持教材的知识推进顺序；章名允许按课程表达需要做小范围优化，不机械照抄目录。
- 二级、三级目录按知识关系组织，而不是按“理论/动画”分栏。分组可以继承理论页、可视化课程或两者混合；只有存在明确从属课程时才建立三级叶子，不为凑层级制造单子项分组。
- 理论内容用静态结构图、对照表和文字完整讲解；只为有独立教学价值的操作或算法提供逐帧播放器。
- 不要求把教材中的每个应用实例都做成动画。数制转换、行编辑、迷宫求解、括号匹配等只在相关理论页中作为简短例子，不设独立课程占位。
- 稳定的算法 ID、概念 ID、路由与学习状态不随目录改名而改变。

当前共有 **12 章、56 个理论专题、60 个动态算法、60 门双语课程**。12 章核心知识均已落地；教材中的普通应用例题只进入相关理论页，不生成虚假动画，也不记为覆盖缺口。

## 第 3 章覆盖明细

教材体系以严蔚敏《数据结构（C语言版）》为准；程杰《大话数据结构》只用于补充经典应用的选材与入门解释，不改变本章的 ADT 定义、存储约定和算法主流程。

| 小节 | 理论专题 | 动态课程 | 覆盖要点 |
| --- | --- | --- | --- |
| 3.1 栈 | `stack-queue-storage` | `stack` | 后进先出、栈顶与栈底、顺序栈 `top = -1` 空栈约定、链栈首结点、push/pop/peek 的真实 Trace |
| 3.2 栈的应用举例 | `stack-recursion` | `infix-to-postfix`、`postfix-eval` | 运算符优先级与括号边界、中缀转后缀、后缀操作数栈求值、向零截断整数除法 |
| 3.3 队列 | `circular-queue`、`stack-queue-storage` | `queue` | 先进先出、循环队列“牺牲一个单元”判空判满、`front`/`rear` 回绕、带头结点链队列 |
| 3.4 栈与递归 | `stack-recursion` | `factorial`、`fib` | 递归调用栈的活动记录、返回地址与局部变量、递归深度；复用既有递归动画，不重复实现 |

本章的 `stack` 与 `queue` 各用一个播放器覆盖两种存储实现，通过输入区的 storage 选择器切换：

- `stack` 支持 `array`（顺序栈）与 `linked`（链栈），默认容量 4，真实展示 `top`、`nodes`、`topId` 和容量边界。
- `queue` 支持 `circular`（循环队列）与 `linked`（链队列），默认容量 5，循环队列最多存 4 个元素；真实展示 `front`、`rear`、回绕 `wrap` 与队满 `full` 步骤。
- 链队列采用带头结点约定：空队列时 `front == rear == head`；删除最后一个数据结点后 `rear` 回到 `head`。原先作为计划占位的 `chain-queue` 专题已删除，由 `queue` 的 `linked` 存储模式覆盖，不再保留重复入口。

`infix-to-postfix` 与 `postfix-eval` 是栈应用唯一新增的两个经典动画。数制转换、括号匹配、行编辑、迷宫求解、离散事件模拟等教材举例不再拆成独立可视化入口，只在栈应用理论页中作为简短说明。两者与 `stack` 共享“栈”这一结构语义，但使用独立的表达式 Trace Schema，避免用结构操作帧伪造算法步骤。中缀转后缀官方示例为 `(3 + 4) * 2 → 3 4 + 2 *`；后缀求值官方示例为 `3 4 + 2 * → 14`。两者强制以 Python 作为导学与官方执行语言，同时保留 JS 预置程序供切换。

## 第 5 章覆盖明细

本章继续以严蔚敏《数据结构（C语言版）》的数组、压缩存储、广义表顺序为准；程杰《大话数据结构》只补充“二维数组即线性表”“广义表像嵌套括号”的直观解释。第 5 章没有把教材所有例题拆成动画：数组地址计算、特殊矩阵映射、广义表定义与存储、m 元多项式结构使用静态图或轻量交互图完整教学，只有“快速转置”“求深度”“复制”三门需要逐帧观察递归或下标变化的算法进入动态课程。

| --- | --- | --- | --- |
| 5.1 数组的定义 | `array-basics` | — | 一维/多维数组、元素与下标、维数与各维长度、数组是下标受限的线性表；3×4 交互图同时展示二维逻辑位置与一维连续内存 |
| 5.2 数组的顺序表示和实现 | `array-basics` | — | 行优先/列优先切换、0 基下标约定、`base=1000`、`w=4` 字节、`A[1][2]` 行优先 1024 / 列优先 1028；公式与图上高亮单元一致 |

| 5.4 广义表的定义 | `generalized-list` | — | 原子/子表/空表、长度只数最外层、深度按嵌套层数、表头为首元素、表尾为删首元素后的表；`()` 与 `(())` 的差别、递归定义、与普通线性表的区别 |

| 5.6 m 元多项式的表示 | `m-variable-polynomial` | — | 一元多项式按指数有序链（第 2 章）与 m 元多项式“项表套因子表”的层次结构；常数项无变量因子；不新增多元加减乘除动画 |
| 5.7 广义表的递归算法 | — | `gl-depth`、`gl-copy` | 原子返回 0、空表返回 1、非空表取子表最大深度加 1；复制先分配新节点再递归子表，副本结构与源等价但节点完全独立；真实 Python 递归 Trace、调用栈、回退与跳帧 |

本章新增 `gl-depth`、`gl-copy` 两门动态课程，共用表达式解析器、输入编辑器、树布局与播放器。输入仅接受括号、逗号、字母数字下划线原子，根必须是表；限制 80 字符、40 节点、最大嵌套深度 8。深度约定为“原子 0、空表 1、非空表 `1 + 子表最大深度`”，默认 `(a, (b, c), ((d), e))` 深度 3，`(())` 深度 2。复制采用先序构造：先为新节点分配编号并接入新父节点，再递归复制各子表；画布用 `c0…` 与源 `n0…` 对应。循环引用、自引用和任意共享子结构不在输入模型内，解析阶段直接拒绝。

`sparse-transpose` 复用原有课程，不重复开发。其真实 Python 入口已是快速转置：先按列统计 `num[c]`，再由 `cpot[c] = cpot[c-1] + num[c-1]` 递推每列在结果三元组表中的起始槽，最后一遍扫描源三元组直接写入目标位置，时间 `O(t+c)`、额外空间 `O(c)`。

### 四种存储结构的图解

- **邻接矩阵**：左侧同一张无向图 `A–B, A–C, B–D, C–D`，右侧 4×4 矩阵。高亮边 `B–D` 时只同步高亮 `A[B][D]` 与 `A[D][B]`；矩阵对称、有向图不必对称、带权图用哨兵区分“无边”和“零权边”、自环落在对角单元、空间 `O(V²)`。
- **邻接表**：同一张图 `n=4, e=4`，无向边在两端各登记一次，共 8 个边结点；明确顶点表、边结点 `adjvex`/`next`、权值域，以及有向图只挂出边、逆邻接表互补的关系。边结点数按方向语义区分 `e` 与 `2e`，空间 `O(V+E)`。
- **十字链表**：有向图 `e1 A→B, e2 A→C, e3 B→C, e4 C→A`。顶点节点含 `firstin`/`firstout`，弧节点含 `tailvex`/`headvex`/`hlink`/`tlink`；同一条弧只存一个节点，同时进入起点出链与终点入链。图解按字段逐条核对链关系，不把 `tlink` 与 `hlink` 混用。
- **邻接多重表**：无向图 `e1 A–B, e2 A–C, e3 B–C, e4 C–D`，每条边只有一个边节点，含 `ivex`/`jvex`/`ilink`/`jlink`，顶点节点含 `firstedge`。`e3` 同时属于 B 的链（`ivex=B`）与 C 的链（`jvex=C`），用于说明“一个边节点被两个端点链引用”，而不是画成邻接表的两个副本。
- **对比表**：覆盖邻接矩阵、邻接表、十字链表、邻接多重表的适用图型、空间复杂度、边记录数、查边 `(u,v)`、枚举邻居和最适合场景，解释同一张图为何可以有不同的物理组织。

### 复杂度口径

| 模块 | 时间 | 空间 | 变量与说明 |
| --- | --- | --- | --- |
| 空闲表 | `O(M · F)` 最坏 | `O(F + B)` | M 操作数、F 空闲块数、B 总块数；首次适应可提前停止，最佳适应通常要扫描完空闲表；有序表可按地址找邻块，但插入/删除仍有表操作 |
| 边界标识 | 找左右邻 `O(1)` | 每块常数标记开销 | 通过块头/块尾读取大小与状态；合并本身只改常数个边界字段，但空闲表的插入/删除取决于其组织方式 |
| 伙伴系统 | `O(M · L)` | `O(B)` | L = log₂(capacity) 为树深，B 为当前块数；等级计算、逐层分裂和逐级合并与 L 成正比，伙伴地址由位运算直接得到；内部碎片为 `blockSize − requestedSize` |
| 标记—清除 | 标记 `O(N + E)`，清除 `O(N)` | `O(N + E)` | N 对象数、E 引用数；标记只走根可达部分，清除仍扫描全部已分配对象 |
| 存储紧缩 | 标记/清除之上增加复制与引用改写，按对象数和引用数计 | `O(N + E)` | 需要计算新地址、搬运存活对象并遍历引用更新目标地址；不能用单一 `O(n)` 概括所有阶段 |

### 分块查找

- 数据不重排；块是原数组上的连续区间，索引项记录每块真实最大值、起点和长度。
- 采用的索引约束是：块最大值严格递增，且后一块的所有关键字都大于前一块最大值；块内允许无序。输入校验失败时拒绝执行并显示双语错误，不会为了“满足条件”而静默排序。
- 查找先顺序扫描索引，进入第一个满足 `max >= target` 的块，再在该块内顺序扫描；目标大于所有索引最大值时直接失败，不进入任何块。
- 真实 Python Trace 分为 `index-compare`、`index-select`、`block-compare`、`found/not-found` 等阶段，分别记录索引比较次数和块内比较次数。官方、自定义和随机输入共用同一播放器；随机场景覆盖中间块命中、块间空隙失败、末块命中、边界关键字、首块命中和全表失败。

### B 树删除

- 沿用现有 4 阶 B 树：每节点最多 3 个关键字、4 个孩子；非根节点至少 1 个关键字，根可为叶，所有叶同深度。
- 删除前先证明关键字存在；不存在时只回放只读搜索，树保持不变。存在时采用自顶向下预修复：下降前保证将进入的孩子关键字数足够。
- 孩子不足时先向左兄弟借，再向右兄弟借；两侧都不够则父关键字下移并与兄弟合并；合并可能继续向上传播；根被抽空时唯一孩子成为新根。
- 内部关键字删除用左子树最大前驱替换，再在叶层删除前驱；若预修复已使目标键下移，则改为在合并后的孩子中继续删除目标键，避免把旧键遗留在叶中。主图始终按真实节点、父子链接和键序重绘，不靠删文本假装删除。
- 六个官方场景分别覆盖叶节点普通删除、内部键替换、左/右借位、合并、根收缩和删除不存在关键字；多次连续删除由自定义输入承担。Schema 校验节点容量、键序、子树范围、叶深度一致性和根的特殊约束。

### B+ 树核心操作

- 沿用 4 阶约定：每节点最多 3 个关键字；内部节点 `k` 个键对应 `k + 1` 个孩子；记录只存在叶节点，内部键只是右子树最小记录的分隔键；叶节点用 `next` 顺序链接。
- 点查找沿分隔键下降到唯一叶节点后再比较记录；插入只写叶节点，叶分裂按 2/2 分配并提升右叶首键，内部节点分裂提升并移除中间分隔键，根分裂创建一层新索引；范围查询从下界叶开始，沿 `next` 前进直到超过上界。
- 分隔键在分裂和根增长后按最终树重新定位，Trace 中的父节点、提升键和范围路径均以真实结构为准；重复关键字在修改前拒绝。
- **本轮覆盖范围明确为查找、插入、叶/内部/根分裂与范围查询，不包含 B+ 树删除。** 课程文案、流程图和参考代码均按此声明，不虚报未实现的操作。

### 键树

| 结构 | 查找 | 插入/删除 | 条件与备注 |
| --- | --- | --- | --- |

| 二分查找 | `O(log n)` | 静态有序表不适用 | 必须有序且支持随机访问；判定树高度约 `⌈log₂(n+1)⌉` |

| BST | 平均 `O(log n)`，最坏 `O(n)` | 平均 `O(log n)`，最坏 `O(n)` | 取决于树高与插入顺序，不保证平衡 |
| AVL | `O(log n)` | `O(log n)` | 严格平衡，旋转维护高度差 |
| B 树 | `O(log_m n)` | `O(log_m n)` | `m` 为阶；节点容量与最小关键字约束决定磁盘访问次数 |

| 哈希表 | 平均 `O(1)`，最坏 `O(n)` | 平均 `O(1)`，最坏 `O(n)` | 依赖哈希函数质量、装填因子与冲突策略；开放定址删除需墓碑 |

### 排序稳定性的讲法

- 稳定性定义为：关键字相等的记录在排序前后保持原有的相对次序。只用 `3, 1, 3` 这样的纯数字无法观察“哪一个 3 原本在前”，因此理论页和动态课都使用带身份的记录，例如 `(3,A)、(1,B)、(3,C)`。
- 稳定性不是算法名字的固定属性，而取决于具体实现。当前课程的口径是：冒泡、直接插入、归并稳定；简单选择、希尔、快速、堆不稳定；树形选择在本项目中用 `(value, originalIndex)` 决胜，因而稳定；基数排序要求每一趟的分配和收集都稳定，否则最终结果不保证正确。
- 新增动态课在输出序列中保留原始身份标签，重复关键字场景可以直接看到 `B → E → H` 之类的原始相对次序，而不是只验证数值升序。

### 树形选择排序（锦标赛排序）

- 叶节点存放真实记录，内部节点存放两个子树当前 `active` 赢家中的较优者；比较键为 `(value, originalIndex)`，相等关键字时原始下标更小者胜出。
- 建树自底向上完成一次；输出根节点赢家后，将该叶标记失效，只重算该叶到根的祖先路径。`affectedNodeIds` 从被移除叶开始、到根结束，其他分支的比较结果直接复用。
- 叶容量补齐到 2 的幂，填充叶不是值为 0 的记录；单记录输入退化为单叶 `L0`，根节点就是该叶。节点总数最多 31，记录最多 12 条，树高与字号保持可读。
- 默认输入 `[8, 3, 11, 1, 7, 2, 9, 4]`；预设覆盖普通乱序、重复关键字、单元素、非 2 的幂长度、逆序和负数。可视化上方显示输入记录，中间显示带比较/赢家/失效/受影响状态的选择树，下方逐步形成输出序列。
- 复杂度：建树 `O(n)`，每输出一个记录更新 `O(log n)`，共 `O(n log n)`；选择树需要 `O(n)` 额外空间（补齐到 2 的幂时不超过 `4n` 个节点）。

### LSD 十进制基数排序

- 从个位开始，每一趟按当前位的 0–9 数字把记录稳定追加到 10 个桶，再按桶号 0–9 依次收集；收集完成后才整体替换 `order`，进入更高数位。
- 当前位由 `(value // 10^pass) % 10` 得到；不足位数的高位按 0 处理，不改变低位已经建立的稳定次序。桶内必须保持进入桶的先后顺序，这是每一趟稳定、最终结果正确的前提。
- 只接受非负整数，范围 0–9999，最多 4 位、16 条记录；负数和超范围输入会被拒绝并显示双语错误，不静默取绝对值、不丢弃负号，也不在某趟偷用比较排序。
- 默认输入 `[170, 45, 75, 90, 802, 24, 2, 66]`；预设覆盖多位整数、不同数位长度、重复关键字、含零、单元素和完全相同关键字。动画按“当前序列 → 当前数位 → 0–9 号桶 → 已收集前缀 → 收集后的序列”展示，空桶不产生虚假收集帧。
- 复杂度按元素数 `n`、基数 `k = 10`、最大位数 `d` 解释：时间 `O(d(n + k))`，额外空间 `O(n + k)`；它不是比较排序，不受 `Ω(n log n)` 比较下界约束，但依赖关键字可拆成有限位。

### 多关键字与链式基数排序

- 多关键字排序区分主关键字与次关键字；LSD 先按次关键字稳定排序，再按主关键字稳定排序，前一趟的次序会被后一趟保留。
- LSD 从最低位开始，适合先分配后收集的稳定实现；MSD 从最高位开始，需要按最高位分组后递归处理各组。两者不是“从哪边读数字”的无关差异，而是控制结构和分组方式不同。
- 链式基数排序用每个桶的 `head` / `tail` 指针串起记录，分配时只改指针，收集时把非空桶首尾相接，避免每趟搬动完整记录。静态图与基数排序课程共用桶、记录节点和稳定次序语义，不另建几乎相同的播放器。

### 九种排序方法比较

| 算法 | 最好 | 平均 | 最坏 | 额外空间 | 稳定 | 比较排序 | 典型适用条件 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 直接插入 | `O(n)` | `O(n²)` | `O(n²)` | `O(1)` | 是 | 是 | 规模小或基本有序；实现简单、常数小 |
| 希尔 | 取决于增量序列，优质序列可接近 `O(n log n)` | 取决于增量序列，通常次二次 | 原始 Shell 序列 `O(n²)` | `O(1)` | 否 | 是 | 中等规模、允许不稳定；需要调增量 |
| 冒泡 | `O(n)`（带提前结束） | `O(n²)` | `O(n²)` | `O(1)` | 是 | 是 | 基本有序或教学演示；实际大规模不优先 |
| 快速 | `O(n log n)` | `O(n log n)` | `O(n²)` | 平均 `O(log n)` 递归栈，最坏 `O(n)` | 否 | 是 | 大规模随机数据、内存较紧；需避免劣质枢轴 |
| 简单选择 | `O(n²)` | `O(n²)` | `O(n²)` | `O(1)` | 否 | 是 | 规模很小、交换次数敏感；比较次数固定 |
| 树形选择 | `O(n log n)` | `O(n log n)` | `O(n log n)` | `O(n)` 选择树 | 是（按原始下标决胜） | 是 | 需要稳定且能接受额外树空间；每轮只更新一条路径 |
| 堆 | `O(n log n)` | `O(n log n)` | `O(n log n)` | `O(1)` | 否 | 是 | 大规模、额外内存受限；不要求稳定 |
| 归并 | `O(n log n)` | `O(n log n)` | `O(n log n)` | `O(n)` | 是 | 是 | 大规模且要求稳定；可接受辅助数组 |
| 基数 | `O(d(n + k))` | `O(d(n + k))` | `O(d(n + k))` | `O(n + k)` | 是 | 否 | 关键字位数有限、可逐位拆分；本课程限定非负十进制整数 |

### 场景选择建议

- 数据规模很小：直接插入或简单选择即可，避免为小数组引入复杂结构。
- 数据基本有序：带提前结束的冒泡或直接插入更接近线性。
- 数据规模较大、平均性能优先：快速排序或堆排序；前者通常更快，后者最坏仍有 `O(n log n)` 且原地。
- 必须保持稳定：归并、直接插入、冒泡；树形选择在本项目实现下稳定，但需要 `O(n)` 选择树。
- 额外内存受限：堆、希尔、快速（仅递归栈）；归并和树形选择需要明显辅助空间。
- 关键字位数有限且可拆位：基数排序可绕过比较下界，但要付出桶空间并保证逐趟稳定。

这些建议是条件化的工程取舍，不是“某算法永远最好”的排名。

### 外存、缓冲区与模拟 I/O 的教学模型

- 记录是带原始身份的排序单位；若干记录组成一个数据块。输入归并段是已经有序的记录序列，初始归并段则由内存中的一批记录内部排序后写回模拟外存。
- k 路归并需要 k 个输入缓冲区和一个共享输出缓冲区。教材的容量约束按 `(k+1)b` 个记录/块单位解释；本课程为了让手机端可读，把缓冲区与块大小都限制在 1–3，并要求同时驻留的记录数不超过总容量。
- 多路课程中每个归并段只暴露 FIFO 缓冲区队首作为候选。缓冲区读入量按 `take = min(块大小, 缓冲区剩余容量, 段内剩余记录)` 推导；模拟读块数为每次非空搬运累加。输出缓冲区达到容量后整块写出，最后残余也必须写出，因此写块数由真实满块与残余块共同决定，而不是预设常数。
- 所有计数器只统计模型事件，并与动画帧同步；输入非法时旧 Trace 会被清空，不会把上次的读写数字残留到新场景。

### 多路平衡归并与败者树

- 默认输入为两段 `[2,5,9]` 与 `[1,6,10]`，缓冲区 2、块 1。相同关键字按 `(value, originalIndex)` 决胜，重复键场景可以直接观察稳定次序，而不是只检查数值升序。
- 支持 2–4 路、最多 24 条记录、每段最多 6 条。空段合法；某段缓冲区耗尽后退出候选，其他段继续，直到所有段都耗尽。
- 课程展示的是最直接的线性候选扫描，`O(n × k)`；理论页与课程说明败者树的真实语义：内部节点保存“败者”，每次只更新赢家叶到根的一条比较路径，可把选择降到 `O(n log k)`。项目没有把普通最小堆或赢家树改名为败者树，也没有伪造一棵并未参与选择的树。
- 真实 Trace 的 `init / read / compare / select / output / flush / done` 全部来自 Python 执行；选择帧只标赢家，输出帧才推进对应段，避免把“选中”和“消费”混为一谈。

### 置换选择的真实运行

- 工作区固定 `M` 个槽位，初态装入前 `min(M,n)` 条记录并全部 eligible；`lastOutput = null` 表示当前段还没有输出。
- 每次从 eligible 中选 `(value, originalIndex)` 最小者写入当前段，然后读入下一条。新记录不小于 `lastOutput` 时继续 eligible；严格小于时冻结。冻结只改变可输出状态，记录仍占槽位，不会被删除。
- eligible 为空时：若当前段非空则封段；若有 frozen 记录则全部解冻、清空 `lastOutput`、开始新段；若既无 frozen 又无剩余输入则结束。相等关键字可以留在当前段，由原始下标稳定决胜。
- 课程没有把输入数组切成固定长度片段再“扮演”置换选择；每个段的分界都由真实冻结与解冻事件产生。因此默认乱序输入形成长度 4、5 的两段，超过工作区容量 3；基本有序输入可以形成更长的段，逆序输入则产生更多短段。
- 结束时真实 Python 断言每段内部按关键字稳定非降序，并断言所有段记录数之和等于输入记录数。动画同时展示输入带、工作区槽位状态、当前段和已完成段，冻结记录始终可见。

### 最佳归并树的代价与虚拟节点验证

- 真实叶 `S0…` 的权重就是初始归并段长度；每次从森林取 k 个最轻根，父节点权重为孩子权重和，累计代价加上父权重。总代价是所有内部节点权重之和，不是根权重。
- 真实段数 `n` 与满 k 叉树不匹配时，按 `d = ((k−1) − ((n−1) mod (k−1))) mod (k−1)` 补零权重虚拟叶。虚拟叶用 `V0…` 标识、虚线边框和“虚拟 0”角标，避免被误认为长度为 0 的真实段。
- 默认 `[3,5,8,11]、k=2` 形成三次合并，内部权重 8、16、27，总代价 `8+16+27=51`，根权重单独显示为 27。`k=3` 的六段示例 `[4,5,9,10,12,15]` 补 1 个虚拟叶，总代价 92；单段输入不合并、总代价 0。
- 树结构与权重由真实 Python 输出，Schema 校验每个内部节点恰有 k 个孩子、父权重等于孩子和、每节点至多一个父节点、森林根集合正确、`totalCost` 等于内部权重和。理论页说明该构造与哈夫曼树的贪心思想相通，但权重是归并段长度、目标是最小化归并代价，不能直接称为哈夫曼编码。

### 记录、块与模拟 I/O 口径

- 索引文件与 ISAM 的记录行是 `关键字, 标签`；倒排记录行是 `R1: 词1, 词2`，关键字已预先分好，不实现中文分词器。
- 块容量只决定教学模型中的分组，不代表真实磁盘块大小。索引文件固定按 1 个索引块 + 1 个数据块计入一次查找；ISAM 固定 1 个索引块 + 1 个主区块，每访问一个溢出节点再加 1 个块。两者均不模拟缓存命中。
- 所有块计数都来自当前输入对应的真实 Python 帧，并且页面明确说明它们是教学模拟，不是磁盘性能测量。

### 索引文件与 ISAM 的真实 Trace

- `file-index` 支持稠密/稀疏索引、3–12 条记录、块容量 2–4。稠密索引每条记录一项；稀疏索引每块取首关键字（末块取上界）一项。查找帧依次为索引探测、读目标块、块内比较、命中/失败、完成；`indexEntryProbes` 记录实际检查的索引项，完成时数据块读取恰为 1。
- `isam` 支持主块容量 2–4、最多 6 个主块和 5 个溢出节点。索引项保存“主块及其溢出链的最大关键字”；查找选择第一个上界不小于目标的主块，否则选择最后一块。主块已满时插入该块专属溢出链，链接后刷新索引上界，并自动重新查找新记录。动态课程完整展示 `insert-overflow → link-overflow → index-update → 重查 → found`。
- 两个 Schema 都校验记录唯一归属、块内有序、索引边界与实际最大关键字一致、溢出链无环且不跨块、最终结果与目标一致。fixture 覆盖稠密/稀疏命中与失败、主区插入、溢出插入和失败查找。

### 倒排索引与多关键字查询

- `inverted-index` 支持 2–9 条记录、每条 1–4 个已分词关键字、1–4 个查询词。构建阶段逐条扫描记录，把记录 ID 追加到对应词的倒排列表；查询阶段逐词取 posting，再按 AND 求交或 OR 求并，结果保持记录准备顺序。
- Schema 校验最终 posting 恰等于“包含该词的记录集合”、posting 顺序与记录顺序一致、缺失词允许空表、`matchedIds` 等于真实交集/并集。缺词参与 AND 时结果为空，而不是把缺词当成匹配所有记录。
- 理论页的多重表图展示同一记录挂入多条次关键字链；倒排图展示记录 ID、关键字、倒排列表和最终结果四层关系。两者都与普通链表、邻接表区分：这里共享的是记录身份，不是图顶点或单链表的物理后继。

### 复用边界与教学表现

- VSAM 不被称为“B+ 树的另一个名字”。理论页说明教材采用的索引区域 + 顺序数据区域模型，以及它和现代 B+ 树索引在动态分裂、占用率和实现细节上的差异；动态部分直接复用第 9 章 `bplus-tree` 的查找、插入与范围查询，不伪造历史 VSAM 存储管理。
- 散列文件复用链地址法与开放定址法课程；理论页额外画出“关键字 → 桶 → 溢出链”，并解释为什么散列适合点查、通常不适合有序范围查询。
- 顺序文件不新增第二套几乎相同的查找动画；需要观察逐项扫描时直接使用 `linear`，理论页负责讲清有序/无序、顺序扫描和范围访问的差别。
