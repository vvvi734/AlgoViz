# Reference code style

AlgoViz 的三语言参考代码同时承担“可运行实现”和“教学材料”两个职责。C/C++ 文件必须遵守以下约定。

## C / C++ formatting

- 使用 Allman 大括号：函数、`if`、`for`、`while`、`struct`、`class` 的左大括号另起一行。
- 统一四空格缩进，不使用 Tab；行宽上限 100。
- 仓库根目录的 `.clang-format` 固化了这条规则：

```powershell
clang-format -i --style=file path\to\file.c path\to\file.cpp
```

## Comments for beginners

不是逐行翻译代码，而是在读者真正需要解释的位置写注释。

1. **文件头**：说明这份实现解决什么问题、建议先看什么、关键不变量、常见错误和复杂度。
2. **每个函数**：至少有一条中文职责说明，写清“做什么、输入/输出是什么、失败/边界怎么处理”。函数内部的实现细节不必重复。
3. **关键步骤**：在指针重接、下标回绕、递归回退、边界判断、易错赋值顺序等位置加行内注释。不要给 `i++` 这类显而易见的语句加注释。
4. **代码与注释一致**：如果实现约定改变（例如循环队列从 `count` 改成牺牲一个空位），文件头、函数注释和行内注释必须同步修改。
5. **术语统一**：`top`、`front`、`rear`、`size`、`length` 等字段第一次出现时明确其含义；不同实现约定不得混写。

新增或修改参考代码时，先读本文件，再运行格式化与对应语言的编译检查。
