# UIX-V01 交付报告：排序与查找柱状图空间优化

## 范围与基线

- 分支：`feat/uix-v01-array-canvas`，从 L1B 最终记录 `7c70176` 创建；`main` 仍为 `10f9a68`，未从落后的 `main` 开发。
- 版本：`0.27.1-uix01`（`package.json` / `package-lock.json`）。
- 范围：只调整 `bubble`、`selection`、`insertion`、`shell`、`quick`、`merge`、`linear`、`binary` 共 8 个入口共享的数组/柱形渲染布局。
- 未新增算法，未修改真实 Python Trace、算法逻辑与执行帧、播放器数据结构、导学默认展开策略、右侧讲解文案、教材目录或其他树/图/链表渲染器；未实施 UIX-02 阶段跳转。
- 另一个 UI Agent 的审查目录只作为只读证据，未作为修改目标。

## 实现内容

### 共享数组画布

- `SortingVisual.tsx` / `SearchVisual.tsx` / `VisualStage.tsx` 的柱高从领域像素值改为轨内百分比：`min(100, cell.height / 165 * 100)%`。领域 `sortingModel.ts` / `searchModel.ts` / `model.ts` 仍输出 `14–165px`，既有领域单测未改。
- 新增 `src/styles/uix01.css`，在 `main.tsx` 末位引入：
  - 普通数组轨：`280px`，最小 `205px`，最大 `340px`；排序数组最高 `360px`。
  - `.bar-item` 成为真实高度的定位轨道；柱体绝对定位在底部 16px 标签上方，最大高度扣除 `--uix-bar-reserve`（普通数组 18px、排序/查找 36px）后再按百分比绘制。
  - 收起导学的桌面焦点态：`.sorting-visual` 与 `.sorting-array-wrap` 填满 stage 剩余高度，数组轨使用 `min(100%, 340/360px)`。
  - 390×844：stage 高度由内容决定，百分比不稳定，因此固定 `220px` 数组轨，避免上一轮迭代出现的 10px 柱高塌陷。
- 归并缓冲区槽位高度由 `46px` 收紧到 `34px`，只压缩空白和内间距；`b0…b7`、值、写回来源和 `8/8` 计数仍完整可读。
- 1366×768 等高度 ≤820px 的桌面窗口额外把排序块间距从 `6px` 收到 `2px`、footer 间距与 hint 上边距各收到 `4px`，只去除空白；插入、希尔、快速的底部图例重新回到 stage 内，柱高与标记均未缩小。归并 1366 基线本身因缓冲区与区间条同时显示而不展示 footer，本批保持该既有行为，未新增裁切。
- 未改主画布与右栏宽度比例：1440 实测主画布 `674.2px`、右栏 `437.8px`；1366 实测主画布 `628.4px`、右栏 `409.6px`。主画布没有被右栏过度挤压，因此未做局部宽度调整，也未缩小右栏字号。

## 已知边界

- 1366×768 受物理高度限制，插入/希尔/归并焦点态柱高原为 158px，现为 169px（1.07×）；保留全部语义标记与播放器后，无法在 363px stage 内达到 1.5×。本批明确不通过隐藏 legend、裁剪缓冲区或把播放器移出首屏来换取数值。
- 归并 1440 焦点态为 217.7px（1.38×），低于其他排序的 1.75–2.05×；原因是临时缓冲区、区间 chips 与主数组必须同时显示。缓冲区已压缩空白，但未删减任何槽位或写回信息。
- 390 使用固定 220px 轨而非百分比；stage 会随内容增高，所以“柱高/stage 内高”占比会因算法辅助区不同而变化，不能直接用 1440 的占比横向比较。
- UIX-V01 完成后停止；未实施 UIX-02，也未新增算法或修改其他渲染器。
